# 技能系统职责与代码约定

适用于技能及关联效果的新增、修改和审阅，不因统一风格而扩大历史代码的重构范围。

本文定义技能系统的运行时架构、职责边界和代码契约，不规定 AI 的任务编排流程。新增技能的 AI 工作流见 [.github/instructions/new-skill.instructions.md](../.github/instructions/new-skill.instructions.md)。

## 核心原则

1. **一层拥有一层，尽量不越级调用**：各层持有和管理直接下一层的引用或实例，通过下一层委托访问效果，不直接读取或代管下下层的内部配置与状态。
2. **Definition 计算数值，不生成显示文本**：公式放在负责该数值的 Definition 中，通过 `CalculateStats(...)` 提供数值及拆解；Skill、Zone、Projectile、Buff 实例提供运行条件并使用结果，不重复实现公式。`CalculateStats(...)` 不返回格式化后的描述字符串。
3. **静态信息读 Definition，效果描述由实例提供**：与状态无关的名称（`Name` / `DisplayName`）和静态 `Description` 保存在 Definition 中。依赖共鸣、运行条件或本次施加数值的效果说明，由 Skill、Zone、Projectile 或 Buff 实例的 `DescribeEffect(...)` / `DescribeAppliedEffect()` 提供并逐层组合。Prefab 上的组件也是实例，可以在给定显式参数时提供无副作用的 `DescribeEffect(...)`；Definition 不实现 `DescribeEffect(...)`，也不负责拼装动态效果说明。

## 职责分工

| 对象 | 职责 |
| --- | --- |
| `SkillDefinition` | ID、名称、静态描述、图标、共鸣类型、技能参数及直接下游引用；通过 `CalculateStats(...)` 计算自己拥有的数值，不生成显示文本 |
| `Skill` | 提供运行条件、选目标、创建及清理实例；`DescribeEffect()` 组合静态描述、自己的计算结果和下一层实例描述 |
| `Zone` / `Projectile` | 持有并封装自身效果配置，处理范围或命中；通过 `DescribeEffect(...)` 描述自身效果，并委托定义计算数值 |
| `BuffDefinition` / `Buff` | 前者保存静态配置并通过 `CalculateStats(...)` 计算数值；后者保存本次施加的来源、状态和数值快照，并通过 `DescribeAppliedEffect()` 描述已施加效果 |
| `BuffHandler` | 去重、重施、队列提交、计时及触发派发 |

技能创建与装配：

- `SkillFactory` 根据 Definition 和等级创建技能，不负责绑定 Owner 或注册到单位。`SkillCell.Apply(unit)` 创建新技能后调用 `unit.AddSkill(skill)`。
- `Unit.AddSkill(Skill)` 先将自身绑定为技能的 Owner，再注册到 `SkillHandler`。
- `Skill` 直接持有对外只读的 `Unit Owner`，通过 Owner 的公开 API 读取状态和执行单位操作。通用敌我及范围查询通过 `Owner.UnitManager` 执行，技能自身负责具体的目标选择策略。
- `Unit.TryGetClosestEnemyInAttackRange` 使用单位缓存的最近活动敌人，并按包含双方体积的有效攻击距离判断；它不重新搜索目标，不等同于 `UnitManager.FindClosestEnemyInRange` 的中心距离查询。
- 技能在绑定完成后才参与描述、生命周期和施放流程。调用流程保证传入有效的新技能实例，每个实例只添加到一个单位，同类型技能不重复添加。`Unit.AddSkill` 不额外检查空值或已有 Owner；`SkillHandler.AddSkill` 只登记技能，不重复检查归属或类型，也不静默去重。
- `SkillHandler` 只管理集合、生命周期、能量和施放队列，构造时直接接收所属 `Unit`，通过它提供事件中的 owner 身份，并在每次能量结算时读取实时每秒能量，不负责绑定技能的 Owner。

引用跟随职责：`SkillDefinition → ZonePrefab/Projectile → BuffDefinition`。技能直接施加 Buff 时可由 SkillDefinition 直接引用 BuffDefinition；同一配置只保留一份，不跨层读取内部细节，也不为分层刻意新增中转类型。

## 计算与描述

- Definition 用 `CalculateStats(...)` 计算自己负责的数值，只返回数值及拆解，不返回或格式化显示文本；`StatBreakdownFormatter` 等格式化工作留在实例的描述流程。
- 与状态有关的说明必须由实例调用 `DescribeEffect(...)`：实例使用显式运行条件取得自身配置的计算结果，组合本层说明，并委托下一层实例描述。描述与执行使用相同配置和计算入口。
- `SkillDefinition.Description` 等静态文案可作为实例描述的前缀；但 Definition 不新增 `DescribeEffect(...)`。Skill 直接施加 Buff 时可以直接引用 `BuffDefinition` 来创建 Buff，预览描述仍应通过对应 Buff 实例的 `DescribeAppliedEffect()`，不能调用 `BuffDefinition.DescribeEffect(...)`。
- 与状态无关的名称和 `Description` 从对应 Definition 读取，不为获取静态信息依赖运行实例，也不维护重复的 `NameStatic`、`DescriptionStatic` 硬编码。
- 结果使用具名元组或小型结构，便于按 `stats.Radius` 等名称访问。单字段结构需注释用途，不引入通用 Stats 框架。
- 已有 Buff 实例的 `DescribeAppliedEffect()` 使用施加时保存的数值快照，不用当前共鸣重新计算旧效果；不因统一命名而单独扩大接口重构。

领域描述的典型委托：

```text
Skill.DescribeEffect()
  ├─ SkillDefinition.CalculateStats(运行条件)
  └─ ZonePrefab.DescribeEffect(运行条件)
       └─ BuffDefinition.CalculateStats(运行条件)
```

以上调用链中，`CalculateStats(...)` 是 Definition 的数值 API；动态文本由调用者实例及下游 Prefab 组件的 `DescribeEffect(...)` 逐层组合。不得直接调用 `BuffDefinition.DescribeEffect(...)`。

## 运行与检查

- `SkillFactory` 的每个技能 ID 必须声明唯一的创建映射及其必需 `SkillDefinition` 类型；映射类型为 `SkillDefinition` 的技能允许使用基类资产。
- 在 Unity 菜单 `Tools/Validation/Validate Skill Definition Registry` 运行注册表校验。它检查 Definition ID 非空且不重复、每个资产 ID 有 Factory 映射、资产实际类型匹配映射类型，以及每个 Factory ID 至少有一个 Definition 资产。
- 所有技能参数均由具体 `SkillDefinition` 持有；无专属参数的技能可映射到基类 `SkillDefinition`。新增或迁移技能后运行注册表校验，确认 ID、类型和资产覆盖完整。

- 模板命名为 `zonePrefab` / `projectilePrefab`，运行实例命名为 `zoneInstance` / `projectileInstance`；创建者明确实例和订阅的清理责任。
- prefab 上的组件也是对象，可直接调用它的 `DescribeEffect` 实例方法，无需创建场景实例；查询只能读取配置和显式参数，不依赖初始化、施法者等运行状态，也不产生副作用。
- `Initialize` 建立本次运行状态，激活和停用负责生命周期。明确数值快照时点；临时固定使用首级配置时留下 TODO，不擅自改动等级流程。
- Buff 集合通过 Handler 队列变更；提前明确来源身份、重施、叠加、到期、伤害类型及施加时序，注意递归伤害和死亡收尾。
- 引用和数值在配置期校验，运行时不加默认值掩盖错误；引用归属变化需同步检查资产。区分静态检查、代码加载、自动测试和实战验证，不能互相替代。
