# 技能系统职责与代码约定

适用于技能及关联效果的新增、修改和审阅，不因统一风格而扩大历史代码的重构范围。

## 核心原则

1. **一层拥有一层，尽量不越级调用**：各层持有和管理直接下一层的引用或实例，通过下一层委托访问效果，不直接读取或代管下下层的内部配置与状态。
2. **Config/Definition 计算数值**：公式放在负责该数值的配置对象中，通过 `CalculateStats(...)` 提供结果；Skill、Zone、Projectile、Buff 提供条件并使用结果，不重复实现公式。
3. **静态信息读配置，状态相关说明读实例**：与状态无关的名称（`Name` / `DisplayName`）和静态 `Description` 在 Config/Definition 中配置；依赖共鸣、运行条件或本次施加数值的效果说明，由实例的 `DescribeEffect(...)` 提供并逐层组合，Config/Definition 不承担动态效果描述的拼装。

## 职责分工

| 对象 | 职责 |
| --- | --- |
| `SkillDefinition` | ID、名称、静态描述、图标、共鸣类型及配置引用 |
| `SkillConfig` / `SkillLevelConfig` | 技能自身的配置、等级数据、Prefab 引用和数值计算 |
| `Skill` | 获取运行条件、选目标、创建及清理实例、组合描述 |
| `Zone` / `Projectile` | 封装自身效果配置、计算委托、描述和范围或命中处理 |
| `BuffDefinition` / `Buff` | 前者保存配置和公式；后者保存本次施加的来源、数值和运行状态 |
| `BuffHandler` | 去重、重施、队列提交、计时及触发派发 |

引用跟随职责：`SkillConfig → ZonePrefab → BuffDefinition`。技能直接施加 Buff 时可直接引用 BuffDefinition；同一配置只保留一份，不跨层读取内部细节，也不为分层刻意新增中转类型。

## 计算与描述

- Config/Definition 用 `CalculateStats(...)` 计算自己负责的数值，只返回数值及拆解，不返回显示文本。
- 与状态有关的说明调用实例的 `DescribeEffect(...)`：使用自身配置的计算结果、组合本层说明，并委托下一层实例描述。描述与执行使用相同配置和计算入口，数值展示复用现有格式器。
- 与状态无关的名称和 `Description` 从对应 Config/Definition 读取，不为获取静态信息依赖运行实例，也不维护重复的 `NameStatic`、`DescriptionStatic` 硬编码。
- 结果使用具名元组或小型结构，便于按 `stats.Radius` 等名称访问。单字段结构需注释用途，不引入通用 Stats 框架。
- 已有 Buff 实例的 `DescribeAppliedEffect()` 使用已施加时保存的数值，不用当前共鸣重新计算旧效果；不因统一命名而单独扩大接口重构。

领域描述的典型委托：

```text
Skill.DescribeEffect()
  ├─ SkillConfig.CalculateStats(运行条件)
  └─ ZonePrefab.DescribeEffect(运行条件)
       └─ BuffDefinition.CalculateStats(运行条件)
```

## 运行与检查

- 模板命名为 `zonePrefab` / `projectilePrefab`，运行实例命名为 `zoneInstance` / `projectileInstance`；创建者明确实例和订阅的清理责任。
- prefab 上的组件也是对象，可直接调用它的 `DescribeEffect` 实例方法，无需创建场景实例；查询只能读取配置和显式参数，不依赖初始化、施法者等运行状态，也不产生副作用。
- `Initialize` 建立本次运行状态，激活和停用负责生命周期。明确数值快照时点；临时固定使用首级配置时留下 TODO，不擅自改动等级流程。
- Buff 集合通过 Handler 队列变更；提前明确来源身份、重施、叠加、到期、伤害类型及施加时序，注意递归伤害和死亡收尾。
- 引用和数值在配置期校验，运行时不加默认值掩盖错误；引用归属变化需同步检查资产。区分静态检查、代码加载、自动测试和实战验证，不能互相替代。
